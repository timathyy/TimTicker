# ADR 0003：区分 UTC 时间点与本地自然日

- 状态：已接受
- 日期：2026-10-28

## 背景

TimTicker 既记录真实发生的时间点，也处理“今天”“计划日期”等日历概念。若所有值都使用本地 `DateTime`，系统时区变化、夏令时、跨午夜和重复时间会产生歧义；若所有值都强制为 UTC，日计划又可能落到错误的自然日。

## 决策

- 已发生或计划发生的绝对时间点使用 `DateTimeOffset`，写入数据库前规范化到 UTC；
- 只表达自然日的值使用 `DateOnly`，不附加时区和 UTC 偏移；
- 展示时间时，在 UI 边界按当前或显式指定的 `TimeZoneInfo` 转换；
- 业务逻辑通过注入的 `TimeProvider` 获取当前时间，不直接调用 `DateTime.Now` 或 `DateTime.UtcNow`；
- 持续时长由起止时间点计算，不把本地钟面时间差直接视为真实时长；
- 跨午夜记录可以完整保存，按日统计时依据目标时区的自然日边界切分；
- 对无效或有歧义的本地时间必须显式校验，不能静默猜测；
- 测试必须覆盖本地日期边界、跨午夜、时区变化以及支持夏令时的时区。

## 影响

模型会同时出现 `DateTimeOffset` 与 `DateOnly`，映射和显示时需要明确转换，但可以避免把“一个时间点”和“一个日历日期”混为一谈。历史记录的展示可能随用户当前时区改变；若未来需要固定原始时区，应另行保存时区标识并新增 ADR。
