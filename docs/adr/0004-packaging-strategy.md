# ADR 0004：Windows 打包策略

- 状态：提议中
- 日期：2026-10-28

## 背景

TimTicker 最终需要在非开发环境的 Windows 10 和 Windows 11 上安装、升级和卸载。MSIX 能提供标准化安装与升级体验，但签名和个人分发可能形成门槛；自包含发布配合安装器更灵活，却需要自行处理升级、卸载和文件关联等行为。

## 当前提议

优先验证 MSIX，同时保留“自包含发布包 + 安装器”作为回退方案。在完成验证前，不把任一方案标记为已接受，也不让业务代码依赖某种安装技术。

最终选择必须验证：

- Windows 10 与 Windows 11 的全新安装、覆盖升级和卸载；
- 无开发环境设备上的 .NET 运行时策略；
- 个人发布场景中的证书、签名和 SmartScreen 体验；
- 自动或手动更新路径；
- 卸载与重装时 `%LocalAppData%\TimTicker` 用户数据的保留规则；
- 应用图标、版本信息、快捷方式和安装包体积；
- CI 或脚本可重复生成安装产物和校验值。

## 决策时点

最迟在 `v0.7.0` 发布工程开始时完成原型验证，并通过新的 ADR 接受最终方案或取代本文。在此之前，开发和测试继续使用 `dotnet run` 与普通 Release 构建输出。

## 影响

暂缓最终选择能避免过早承担签名或安装器维护成本，但 v0.7 前必须预留专门时间在干净设备上验证两种路径。应用数据固定在安装目录之外，使两种候选方案都能遵守升级和卸载时的数据保留要求。
