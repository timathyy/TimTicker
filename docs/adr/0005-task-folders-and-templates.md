# ADR 0005：任务文件夹与模板生成记录持久化

- 状态：已接受
- 日期：2026-11-04

## 背景

`v0.5.0` 需要让任务像文件资源一样按任意层级整理，并让一个自动任务文件夹生成的系列任务始终集中在该文件夹中。自动周期生成还必须能在应用重启后继续，并且不能因重复启动而为同一周期生成多份任务。

## 决策

- 文件夹是 SQLite 中的业务实体，不映射为操作系统目录；每个文件夹保存可空的 `ParentId`，因此可以形成任意深度的树；
- 文件夹名称只要求在同一父目录内唯一，不同路径可以出现同名文件夹；
- `TaskItem.FolderId` 保存任务所在目录，空值表示根目录；旧任务升级后留在根目录，不做隐式搬迁；
- 创建自动任务文件夹时，在当前目录中以同一事务保存文件夹和生成规则；它与普通文件夹混排，也可存放普通任务和子文件夹；
- 带生成规则的文件夹通过 `TaskFolderKind`、强调色图标和“自动”标记区分，不在界面中建立独立模板区域；
- 模板保存标题规则、默认描述和优先级、生成方式、周期倍数、开始日期、下一个系列序号和最后自动生成日期；
- 自动周期支持按天、按周和按月。应用启动时补齐截至当前业务日尚未生成的周期；手动生成不占用自动周期日期；
- 生成的任务保存模板标识、系列序号和可空的自动周期日期，并使用数据库唯一索引约束“模板 + 序号”及“模板 + 自动周期日期”；
- `%y`、`%m`、`%d` 分别生成四位年、两位月和两位日，`%n` 生成从 1 开始的十进制系列序号；
- 自动生成的任务不可移出来源文件夹，避免系列记录遗漏；用户手工创建的任务不受此限制。

## 影响

文件夹树、任务分类和自动生成状态可以随数据库一起备份、迁移和恢复，也能通过外键、事务与同级唯一约束保证一致性。这里的“文件夹”是应用内持久化目录，不是用户磁盘上的真实目录。若未来需要导出为操作系统目录，应设计独立的导出功能，而不是改变当前数据模型。
